# Agent Guide for foggy-laravel

## Project context
- Framework: Laravel 12
- PHP: 8.4
- Frontend build: Vite 5 + Bootstrap 5
- Auth: laravel/ui auth routes
- Main domain concerns: user file uploads, pin-based file access, public file sharing

## Primary objective
Keep changes secure, testable, and idiomatic Laravel. Prefer built-in framework features over custom low-level PHP behavior.

## Non-negotiable standards
- Keep controllers thin. Move validation to FormRequest classes and business logic to services/actions.
- Use dependency injection and typed return values.
- Use Eloquent scopes/relationships instead of repeating query logic.
- Use Storage and Response helpers for file operations; avoid raw `header()` and `readfile()` in controllers.
- Never disable CSRF per-route unless there is a verified external webhook requirement.
- Do not place executable business logic inside route definitions.
- Keep locale, auth, and request shaping concerns in middleware.
- For multi-step write operations (file + DB updates), use DB transactions.

## Security rules
- Validate all uploads with explicit file rules (size, mime/mimetypes, extension where needed).
- Sanitize and normalize user-provided file names and path inputs.
- Avoid exposing raw storage paths.
- Authorize every file read/write/delete/public action.
- Use signed URLs or short-lived tokens for share links where possible.
- Do not trust client metadata (size, mime, name) without server validation.

## Route and middleware rules
- Group routes by middleware, prefix, and name.
- Prefer Route model binding and policy checks.
- Keep route names stable when possible.
- Use dedicated middleware for locale resolution instead of inline route-file logic.
- Configure global CSRF exceptions in `bootstrap/app.php` only when truly required.

## Data and model rules
- Use fillable/guarded intentionally and prefer mass assignment with validated data.
- Cast numeric, boolean, and datetime fields in models.
- Avoid magic strings; prefer constants/enums/config values.
- Keep migrations forward-only and deterministic.

## Testing rules
- Add or update feature tests for every behavior change.
- Include upload and authorization tests for file flows.
- Use factories and seeded states, not hard-coded assumptions.
- Run before merge:
  - `php artisan test`
  - `./vendor/bin/pint --test`

## Existing project hotspots to improve incrementally
- Replace raw file download responses in file controllers with `response()->download()` or streamed responses.
- Move inline locale selection from routes into middleware.
- Replace route-level `withoutMiddleware(VerifyCsrfToken::class)` for upload endpoints with safer CSRF strategy.
- Add request classes for upload/pin/public file actions.
- Introduce transactional write path where storage and DB are updated together.
